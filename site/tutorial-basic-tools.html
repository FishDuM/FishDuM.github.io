Tool Basics

先把最常见的开发工具学会

当你开始做项目后，真正高频出现的不是复杂算法，而是创建文件、进入目录、安装依赖、运行项目、提交代码、定位报错。

文件与路径 终端命令 编辑器 Git 与 GitHub 看报错
01

文件、文件夹、路径是什么

如果你对“代码保存在什么位置”没有感觉，后面做项目会很容易混乱。一个项目的第一步，往往不是写代码，而是把文件结构整理清楚。

文件

`index.html`、`app.js`、`logo.png` 都是文件，分别保存网页、代码和图片。

文件夹

`site`、`images`、`src` 这类目录用来分类保存不同文件。

路径 路径就是“这个文件具体放在哪里”的描述，比如 `site/index.html`。
后缀名 像 `.html`、`.css`、`.js` 这样，告诉系统文件是什么类型。
相对路径 从当前文件出发去找另一个文件，比如 `./style.css`。
02

终端：你和电脑直接说话的窗口

终端并不可怕，它只是一个没有图形按钮的操作入口。很多开发命令在终端里会比鼠标点来点去更快，也更准确。

几个最常见的命令
cd site
ls
mkdir demo
code .
`cd site` 进入 `site` 目录。
`ls` 查看当前目录里有什么。
`mkdir demo` 创建一个名为 `demo` 的新文件夹。
`code .` 用 VS Code 打开当前目录。
终端里最常见的误区

不是命令记不住，而是不知道自己“当前在哪个目录”。很多操作失败，根本原因只是命令执行的位置不对。

03

VS Code 和 IDEA 分别适合什么

它们都能写代码，但擅长的场景不一样。你不用一开始就把所有功能都学会，只要知道在不同阶段用哪个更顺手即可。

VS Code

轻、快、插件多，特别适合 HTML、CSS、JavaScript、Vue、React、Python 等方向。

IntelliJ IDEA

对 Java、Spring Boot、Maven、调试和大型工程支持更强，适合后端主线。

04

Git 和 GitHub：给代码留“时间记录”

Git 是版本管理工具，GitHub 是常见的远程仓库平台。你可以把 Git 理解成“本地存档机”，把 GitHub 理解成“云端备份柜”。

`git init`

把当前目录初始化成一个 Git 项目。

`git add .`

把当前修改加入暂存区，表示“这些改动准备保存”。

`git commit -m "..."`

正式生成一个版本快照。

`git push`

把本地版本推送到远程仓库。

日常最常用的流程
git status
git add .
git commit -m "完成个人主页第一版"
git push
要尽早养成的 Git 习惯
  • 每做完一个小功能就提交一次，不要攒太久。
  • 提交信息尽量写清楚，不要总写 `update`。
  • 做大改动前先提交一版，出问题更容易回退。
05

怎么看报错，才不会一报错就慌

报错不是敌人，报错其实是在告诉你：哪一行附近有问题、哪种规则不符合、程序找不到什么东西。越早建立“读报错”的习惯，成长越快。

先看位置 大多数报错都会告诉你大致在哪一行出问题。
再看关键词 比如 `not defined`、`cannot find`、`unexpected token`，通常已经说明了问题类型。
最后缩小范围 优先检查你最近改过的那一小段，不要一口气盯整页代码。
最简单的练习方式

故意把一个变量名写错一次，观察报错内容，再自己修回来。主动体验一次“为什么会报错”，比只看说明更容易学会。
